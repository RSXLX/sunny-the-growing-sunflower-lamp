# 制作记录、照片与返工

软件入口：衣橱 → 实体外装档案 → 制作记录。用户当前没有硬件，因此无需填写实际制作记录。自动化测试使用临时数据库和合成照片，不代表发生了真实打印。

## 状态与尝试

- 待制作 → 制作中 → 已打印 → 装配检查通过。允许已有实际打印结果的档案从待制作直接登记已打印。
- 制作中、已打印或装配检查通过可以登记失败。已绑定档案需要先解决设备安装/解绑生命周期，不在本轮直接改为失败。
- 失败 → 同版本重试：保留失败日志和附件，尝试次数加一，继续固定引用原制造版本。
- 失败 → 建立关联重制档案：从同一设计的已批准版本中选择，生成独立实例/NFC 身份，保存源实例和新旧版本关联；旧档案保持失败。
- 补充证据：追加记录，不改变制作状态或尝试次数。不能编辑或覆盖旧记录；填错时追加更正说明。

实例必须有固定制造版本且不是模拟/来源待核实档案。模拟绑定与真实制作记录分开。版本撤销后不能开启新尝试或登记制作通过，但仍能补记发现的失败及证据。

制造版本批准、人工制作陈述和设备报告有不同含义。勾选人工检查、上传照片或者写入测量值，不会自动验证材质、电气安全、校准或测量真实性，也不自动赋予任何认证。

## 记录内容

材料、打印设备/服务、说明、测量项目、数值、单位及方法/条件。每条最多 20 个测量项目，单位支持 mm、°C、g、N，数值要求有限且在 -10000 至 10000 之间；此范围只是输入边界，不是安全通过阈值。登记已打印时必须填写实际材料和设备；装配检查沿用接口配合、可靠固定、电气及温度人工确认。

每条记录最多 3 张 PNG/JPEG，每张上传及清理后均不超过 2 MiB；账号合计上限 500 张/300 MiB。图片完整解码、校正 EXIF 方向、清除元数据后存为 PNG，限制像素和边长。哈希对应清理后的图片，不代表相机原文件鉴证。

照片只由所属实例的本人读取，公开设计与制造包不会带出照片。原图元数据不会被保存。读取时核对大小和 SHA-256，损坏或缺失返回冲突错误，其他账号返回不存在。

## 一致性与恢复

`POST /api/instances/:id/records`：`stage`、`expected_stage`、`request_key`、`note`、`acknowledge`、`details`、`photos`。`photos` 使用 `{name,data_base64}`；测量位于 `details.measurements`，每项为 `{name,value,unit,method}`。

同一实例和提交标识的相同请求只写一条记录；改变内容后复用该标识会被拒绝。期望状态冲突要求重新读取，不会静默覆盖。界面保留提交标识供网络重试；若提交内容需要修改，应重新打开表单。

`POST /api/instances` 支持 `source_instance_id`、已批准的 `manufacturing_version_id`、`note` 和 `request_key`；普通制作档案创建也可使用幂等标识。

记录、照片索引和状态在一个 SQLite 事务内提交。写照片或数据库提交失败会回滚并清理本次文件。进程异常退出仍可能留下没有数据库引用的文件；它们不通过读取 API 暴露。完整的数据/模型/照片一致性备份与孤立文件整理尚未实现，应作为后续交付能力完成。

迁移 v3 增加照片索引、重制关联、尝试次数及幂等字段。既有失败/重试历史按原时间和行顺序回填尝试次数，原记录 ID、正文与时间不变。迁移前继续执行数据库一致性备份。

## 软件验证

`test_fabrication.py` 覆盖私有照片、元数据清理、并发重试、更改内容冲突、失败历史、改版重制、权限、无效测量、过期状态、撤销后补记失败、照片损坏、磁盘失败回滚和旧库迁移。

`browser_fabrication.py` 在隔离 HTTP 服务中验证移动表单、照片和测量回读、重试去重、尝试编号、关联重制和跨账号拒绝。没有启动生成 Worker 或付费 API。
