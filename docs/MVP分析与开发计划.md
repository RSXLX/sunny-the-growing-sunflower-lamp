# BLOOM MVP 分析与开发计划

评估日期：2026-09-21。目标假设：单机或可信局域网内，完成一盏真实台灯的端到端演示；暂不按公开销售或云端多租户产品规划。以下范围、工期和新增验收指标为建议，尚未经过团队排期确认。

## 1. 结论

现有交付是已有软件 MVP 加未完成实物验证的硬件工程原型，值得继续开发，不需要从零重写。最重要的工作是打通“记忆 → 视觉描述 → 模型 → 人工工程修正 → 打印 → 装配 → NFC → 灯光与记录”。

当前最大不确定性在制造、光学、实际电气与固件联调。先证明一个真实外装能完成闭环，再增加三套外装、二次创作和展示包装。六个页面已经存在，继续扩页面不应占用关键路径。

## 3. 已有能力与差距

| 部分 | 当前依据与能力 | MVP 还需完成 |
|---|---|---|
| 工作台 | `web/app.js`、`viewer.js`；六页、本地账号、3D 预览、制造下载 | 原生浏览器实际访问、移动布局、GPU/降级路径复测 |
| 后端 | `app/service.py`、`store.py`；SQLite、私有记忆、设计/实例分离、公开二创、任务恢复 | 制造版本、人工修正版回填、制作证据关联及异常提示 |
| Tripo | `app/providers.py`；提交、轮询、下载、未知提交停止、费用确认 | 真实账户合同验证、返回资产兼容性、一次真实成功链路 |
| 模型适配 | `adapt_live_model`；GLB 转换、压扁、环形裁切与载体 | 连通性、薄壁、实际安装界面和人工修改结果审核 |
| 制造状态 | `review_design`、`stage_instance`；文本审查、人工推进阶段 | 审核对应哪个 STL、材料/尺寸/照片、失败与返工记录 |
| 设备协议 | 命令回执、TTL、事件去重、设备 token、模拟器隔离 | ESP32 实际上报、断网重连、过期命令与绑定异常验证 |
| 固件 | PlatformIO 源码、PWM、PN532、按键、温度锁定、离线缓存 | 完整编译、烧录、模块兼容、NFC 与双热源台架验证 |
| 机械/光学 | OpenSCAD、17 个 STL、BOM、分体投影方案 | 按实购物料改图、试片、可靠固定、真实成像与整机装配 |

代码层面的具体缺口：

1. `review_design` 目前凭资源目录存在、确认框和文字记录即可进入 reviewed；不能证明最终可制造 STL 已存在并通过审核。应把“设计审查”和“允许制造”区分开，允许查看原稿，但实际制作必须绑定已批准的制造版本。
2. `stage_instance` 目前只推进 planned → printed → verified，并不保存尺寸或照片等制作证据。首版可以用本地证据文件和结构化记录，不必开发复杂文件平台。
3. 人工修正后的 STL 尚无正式上传/导入与不可变版本关系。直接覆盖资产目录会让旧审查、旧实物与新文件混在一起。
4. 单服务进程和一个生成 Worker 适合本地演示。先保留架构；模型转换建议放入有超时、文件大小和资源限制的子进程，避免异常模型拖住服务。无需为当前规模引入微服务。

## 4. 建议冻结的 MVP 范围

必须完成：

- 一盏真实灯、两路单色调光、实体按键、故障关闭。
- 默认向日葵外装和至少一件由真实 Tripo 原稿经人工修正后制造的外装。
- 一条私有记忆到真实外装的来源链；只发送用户确认的视觉描述。
- NFC 写入、读回和安装识别，网页展示真实设备状态；模拟状态持续有明确标记。
- 制造版本和实物实例对应，能追溯原稿、修正版、最终 STL、材料、照片和审核记录。
- 两个账号完成公开设计和二次创作，不能访问对方私有记忆。

增强演示：第三套星夜外装、第二种手动光影片、进一步美化房间。分体投影先做光学可行性验证；若无法达到事先约定的展示效果，应显式收缩对外承诺，不能用网页效果替代。

暂不做：RGB、机械生长/转头、语音、摄像头、电池、自动换片、付费社区、自动下发打印、原生手机 App、云端多租户。保留已有六页，但按核心闭环排序工作。

## 5. 开发阶段与验收门槛

估算按一名全栈开发、一名能承担嵌入式与结构联调的工程人员协作，另有打印支持；约 4–6 周。采购、打印排队、返工与账户开通可能延长日历工期；单人兼任建议预留 6–8 周。均为规划估算。

| 阶段 | 时间估算 | 工作与交付 | 完成条件 |
|---|---|---|---|
| M0 基线与范围 | 1–2 个工作日 | 固定工具版本、建立独立测试数据目录、运行原生浏览器闭环、登记失败项；冻结单灯/外装/光学目标 | 能重复从启动到参数化制造包；保留测试日志；确认硬件与打印资源 |
| M1 台架可行性 | 3–5 个工作日，另计到货 | ESP32 全量编译；LED、按键、PN532、NTC 台架；LED/插片/镜片光学试验；实购物料尺寸表 | 两路控制与真实回执成立；NFC 可读写；传感器异常能关闭；光学有实拍及约定条件 |
| M2 结构与制造版本 | 5–8 个工作日 | 修支架、镜片/扩散片保持、灯板/模块固定；试片；新增制造版本和证据回填 | 配合试片通过；审核绑定文件哈希；未完成制造审核的版本不能推进实物制作 |
| M3 真实生成与装配 | 5–7 个工作日，另计打印 | 小批真实 Tripo 联调；保存 raw.glb；工程修正；切片打印；装配和标签绑定 | 至少一件 AI 来源外装能真实装灯；完整来源链可追溯；失败/未知提交不重复产生新任务 |
| M4 稳定性与演示 | 3–5 个工作日 | 断网、重启、过期命令、NFC 重复读取、数据备份恢复、实际光学与整机检查、双账号演示 | 达到下述验收清单；交付运行说明、证据和限制列表 |

关键依赖：实购物料尺寸 → 修图 → 试片 → 整件打印 → 装配。真实 Tripo 生成必须经过工程修正后才能进入打印。软件补缺可与台架并行；整套打印不能抢在配合和光学试验之前。

## 7. 硬件阻塞项与资源

原包 `03_补充说明/打印前必读_已知问题与验证边界.md` 已记录：投影斜托架可能低于底板底面约 13.3 mm；镜片压环缺明确锁定方式；扩散片缺独立保持件；灯板、按键、PN532 与底盖尺寸/固定存在假设。这些是原交付记录，本次未重新计算 CAD。

首批只准备关键样件：ESP32、PN532、可写标签、两路低功耗 LED 与驱动、按键、NTC、供电保护、透镜、灯杆以及两种配合试片。完整采购规格以包内 BOM 为起点，按实际型号测量与复核；本报告不提供未核实的价格、库存或采购链接。

需要落实：硬件执行人、板卡和光学件、打印机或外包渠道及材料、卡尺/电气/温度测量工具、Tripo 账户和单独批准的调用预算。先对原型取样和打印服务询价；预算拆分为电子模块、光学/机械件、试片、整件打印/返工、API 与工具，不把开发工时混入材料成本。

单个 NTC 不能证明主灯和分体投影两个热源都受覆盖。需在台架阶段形成双热源监测/保护方案并验证，再决定整机连续运行条件。报告不以软件阈值替代材料、电气或产品认证结论。

## 8. 最终验收清单

下列均为待实现/待测目标，不是现有成绩：

- 软件：从私有记忆、生成、审核、制造版本、实物、NFC 到安装记录走通；第二账号只能获得公开设计。
- 可追溯：每个演示实物对应一个固定制造版本；原稿、修正版、最终 STL 和证据一致，不用后续文件覆盖旧记录。
- 设备：20 次换装至少 19 次正确识别（沿用原产品文档目标）；重复读取同标签不新增重复成长事件；保存每次结果和失败原因。
- 离线：缓存外装断网仍可识别，本地按键可用；重连后不执行已过期命令；掉电未上传事件可能丢失的边界明确展示。
- 光学与机械：记录投射距离、环境条件和实拍；手动换片真实生效；记录接口、紧固、镜片/扩散片保持和稳定性结果。
- 温度与电气：覆盖两个热源、异常传感器和故障关闭；由硬件执行人按实购物料与材料要求明确测试条件、限值和停止条件，保存测量结果。
- 演示：从真实设备发起调光/换装；生成和打印若为历史过程，明确展示对应任务和录像；不得宣称即时打印或全自动制造。

通过这些门槛可以称为“真实硬件 MVP 演示完成”；不等同于可量产、可销售或取得灯具认证。
