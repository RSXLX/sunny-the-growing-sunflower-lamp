# BLOOM 开发板块与总体排期 v3

规划日期：2026-09-22。本版用于开发拆分、排期和验收讨论，替代 v2 作为当前规划入口。未修改业务代码、未调用付费 API、未采购、未报名；所有新增设计均为待实施方案。

## 1. 目标与交付层次

产品定位：用户把生活记忆或选定图片，通过 Tripo 创作成可更换的实体外装；装到同一台灯上后，可识别、点亮并回看来源。

| 版本 | 用途 | 明确交付 |
|---|---|---|
| R0 参赛目标版 | 证明核心体验与真实工具贡献 | 一盏主灯、默认外装和一件 Tripo 实体外装、真实生成/预览/制造追溯/NFC/点亮、可操作软件与演示材料 |
| R1 完整 MVP | 受控环境的少量用户试用 | R0 + 图片输入、可视化适配、正式制造版本/返工/证据流程、隐私和删除、公开二创、投影实测、运维和完整回归 |
| R2 可选增强 | 基于试用反馈扩展 | 第三套外装、更多生成样例、重复几何操作自动化；确有需要再做公网托管 |

本版把完整投影体验放在 R1，不能以未完成投影的 R0 宣称完整“房间光影”体验。若决定完整 MVP 也取消投影，应正式更新范围和叙事，不直接跳过验收并标记完成。

完整 MVP 包含两个可选输入入口：文字、图片；它们共用生成、版本、制造和设备链。用户不必按顺序使用两个入口。主灯控制是硬件基本功能，分体投影有独立可行性关卡。

不做：自动生长机构、自动转头、聊天语音、摄像头、自动换片、电池、支付/物流、账号间设备所有权转移、大型社区和量产认证。

## 5. 架构与关键边界

```text
浏览器（本机或可信局域网）
  → API / 会话 / CSRF / 对象权限
     → 记忆与设计服务 → SQLite + 私有文件
     → 单进程生成 Worker → Tripo → 原始资产
                             → 有限资源的转换进程 → 制造候选版本
     → 审批/制造记录 → 固定版本的制造包 → 人工切片/打印/后处理
     → 设备 poll / commands / events ↔ ESP32 ↔ NFC / 灯光 / 保护
```

- 只有确认后的输入发送第三方；文件访问按资源权限，而不是“知道 URL 即可”。
- Tripo 任务成功仅表示生成成功。制造通过由具体文件版本和检查记录决定。
- 物理实例引用固定制造版本；安装与移除是事件，不覆盖制造历史。
- 网络状态与命令期望状态不同。前端等待真实回执，不提前显示灯已执行。
- 保护在设备本地生效；断网不能绕过保护。
- 公开分享使用显式发布的文件快照；不能遍历整个设计目录自动打包所有新增文件。
- 本地应用不等于公网服务。若评委要求公开链接，需要另外完成部署工作或确认可接受的本地运行包。

详细数据、状态、接口与一致性约定见 `03-数据接口与业务规则.md`。

## 11. 完成定义、测试和发布

每个任务完成需要：实现/实物存在；适用的回归通过；交付物和证据路径可定位；环境/源码/固件/接口/制造版本明确；遗留限制已记录。状态为 planned/in_progress/blocked/review/done，不能把“已写代码”直接等同于 done。

质量门禁、证据模板、失败处理与发布清单详见 `04-验收与交付计划.md`。根证据采用日期和任务 ID 组织，新结果不覆盖原包历史记录。

## 12. 风险与优先决策

| 风险 | 提前动作 | 处理原则 |
|---|---|---|
| 模型不可制造 | W1 真实样例，W3 首件修正 | 允许明确标注的人工修正；保留特征和来源，不用演示模型替换 |
| 生成协议/格式不兼容 | 验证实际账户、请求与资产 | 固定已验证配置；版本升级单独检查 |
| 电气/结构/光学失败 | 先台架和试片，后整机 | 不凭几何报告判断实体通过；投影失败明确影响 R1 范围 |
| 人员跨技能不足 | 明确硬件和建模工作承担人 | 外包或增加工期，不能默认全栈兼具全部硬件能力 |
| 软件复杂度膨胀 | 单服务、最小数据增量、复用六页 | 不做全框架重写、自动 DFM 平台或社区基础设施 |
| 发布时间过紧 | 在早期关卡按事实缩小交付 | 参赛切片与完整 MVP 分开，保留未完成状态 |

开发启动前需要落实但本轮不阻塞规划的四项信息：实际参与人员与投入时间、现有板卡/打印资源、Tripo 账户和预算、是否必须在 10 月 5 日交付实体演示。答案将调整排期，不改变对真实证据的要求。
