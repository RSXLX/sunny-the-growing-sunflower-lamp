# BLOOM 数据、接口与业务规则 v3

2026-09-22。以下除“当前”栏目外均为拟议实现契约，尚未编码；任务 DA-01 完成时冻结。路径相对于实际应用目录。目标是最小扩展现有系统，避免为原型引入分布式基础设施。

## 1. 现有对象与增量模型

当前 SQLite 表：users、sessions、memories、designs、instances、devices、commands、events、favorites。生成状态和 task_id 存在 designs；实例目前只关联 design_id，没有固定制造版本。

建议新增四个业务/资产表及迁移记录表。表名是候选，实现时可调整，但下述约束必须保留。

| 对象 | 拟新增/扩展字段 | 核心约束 |
|---|---|---|
| schema_migrations（新增） | version、applied_at | 一次性版本迁移；旧数据库不可仅用 CREATE IF NOT EXISTS 升级 |
| assets（新增） | id、owner、kind、path、sha256、bytes、media_type、created、source_asset_id | 实体文件只由服务器命名；内容就绪后提交元数据；文件哈希确定内容 |
| memories（扩展） | reference_asset_id（可空） | 记忆本身保持私有；修改图片不改写已提交任务的输入快照 |
| designs（扩展） | input_mode、input_asset_id、input_snapshot、model_version、request_snapshot、postprocess_state、published_manifest | 复用现有 task_id/attempts/next_run；首次成功提交的参数不可被后续编辑重写 |
| manufacturing_versions（新增） | id、design_id、revision、interface_version、transform_json、artifact_manifest、checks_json、review_state、review_note、reviewed_by、reviewed_at、created | UNIQUE(design_id,revision)；已冻结版本的文件集合不可变；版本批准必须绑定确切文件和检查记录 |
| instances（扩展） | manufacturing_version_id、fabrication_state、binding_state | design_id 与关联版本必须一致；绑定状态不代替制造状态；真实和模拟来源明确 |
| fabrication_records（新增） | id、instance_id、attempt_no、kind、material、machine、measurements_json、evidence_asset_ids、note、created_by、created_at | 追加记录；返工不覆盖原失败记录；证据文件须存在且有访问控制 |
| commands/events（复用） | 必要时扩展 payload，保留既有 ID/状态 | 事件重试稳定 ID；同 ID 不重复应用；旧事件不能改变为不同内容 |

接口定义以版本文件保存；制造 manifest 包含该接口定义的哈希。只有接口名称不足以证明参数未变。

R0 加速切片可先使用本地 manifest 和导入命令表达制造版本；R1 需迁入上述可管理对象。不能因 R0 使用文件简化方案而失去版本与实例的固定关系。

## 2. 状态机

### 2.1 生成与后处理

保留已有生成路径：queued → submitting → polling → downloading；参数化模式 queued → generating。provider 成功后，后处理状态另外记录 processing / ready / manual_required / failed。前端明确呈现“原稿已生成，但需要人工处理”。

- submitting 中断且没有可靠 task_id：进入 submission_unknown，不自动重新 POST。
- 已知 task_id：重启后恢复查询/下载，不创建新供应商任务。
- 查询网络失败：有限次数退避；超限停下并保留可核对信息。
- 供应商明确失败：记录失败；重新生成是新的用户操作和幂等键。
- 转换失败：保存可用原稿，允许人工导入；不能把整个设计标记为可制造。
- 超时取消只保证本地停止后续工作；不声称第三方已退款/取消任务，除非有供应商明确结果。

### 2.2 制造版本

```text
draft → submitted → approved
                  → rejected
approved → revoked（撤销批准，文件不变）
```

- draft 的上传编辑区可替换临时文件；submitted 后文件集冻结。
- 修改冻结版本的几何、接口或制造相关配置，创建新的 revision。
- approved 必须有最终文件、单位/接口、检查记录、审核主体与时间。
- 缺少自动检查结果是待检查，不等于通过；需要人工项的明确记录。
- revoked 阻止新制作/真实绑定；既有实物不删除，显示其版本已撤销，人工判断后续处理。
- 发布展示与制造审批分开。公开原稿可讨论，但不可把未经制造批准的原稿当作可制造版本交付。

### 2.3 实物制作与绑定

```text
fabrication_state: planned → printing → printed → verified
                             ↘ failed → printing（新 attempt）
binding_state: unbound → pending → bound
                         ↘ failed/expired → pending（新命令）
```

- 实物实例创建时固定一个 approved 制造版本。模拟器可以使用演示版本，但模拟来源不得升级为真实验收。
- 同一制造版本重印：追加新 attempt 记录；若形成额外独立成品，创建新实例。
- 改几何/接口后重做：新版本和新实例，并记录替代关系，不覆盖旧实物。
- 只有 verified 的真实实例能发起真实绑定。绑定成功需有效命令、标签写入与读回、设备事件相互对应。
- bound 表示身份绑定，不代表当前安装；当前安装由设备 reported 与安装/移除事件表达。
- 移除检测规则在 DV-01 冻结：需基于可测的去抖/超时，而不是网络瞬断直接判定移除。阈值通过台架确定。
- 标签可被复制，不能作为账号身份或版权证明。凭据边界仍为账号和设备 token。

## 3. 拟议接口清单

现有接口继续复用，新增路径在 DA-01 评审后确定，不一次性重写全部 API。

| 方法与路径 | 当前/拟议 | 用途和约束 |
|---|---|---|
| POST /api/assets | 新增 | 接收图片或模型；服务端指定允许 kind/格式/大小；返回 asset_id，不返回文件系统路径 |
| GET /api/assets/:id | 新增 | 按私有/公开 manifest 权限读取；不凭 ID 跳过所有权 |
| POST/PATCH /api/memories | 扩展既有 | 关联可选 reference_asset_id；只接受当前账号素材 |
| POST /api/designs | 扩展既有 | input_mode、prompt/input_asset_id、确认发送、费用确认；保留 Idempotency-Key |
| GET /api/designs/:id | 扩展既有 | 返回任务、原稿、后处理、版本摘要；公开响应剔除私有字段 |
| POST /api/designs/:id/recover | 复用 | 恢复经用户核对的 task_id；保持现有权限和状态限制 |
| POST /api/designs/:id/versions | 新增 | 从资产与变换建立制造候选版本；文件须就绪，接口快照固定 |
| GET /api/designs/:id/versions | 新增 | 仅返回调用者可见版本/公开快照 |
| POST /api/versions/:id/submit | 新增 | 冻结文件集并请求审查；需要完整候选清单 |
| POST /api/versions/:id/review | 新增 | approve/reject/revoke；预期旧状态和记录必填；并发修改返回冲突 |
| GET /api/versions/:id/package | 新增 | 按固定 manifest 打包；禁止包含未列出的新文件；不可用状态明确提示 |
| POST /api/instances | 扩展既有 | 接受 manufacturing_version_id；对真实制作执行 approved 门槛 |
| POST /api/instances/:id/records | 新增 | 追加制作/失败/尺寸/照片等记录；阶段更新与记录在同一事务 |
| POST /api/instances/:id/stage | 兼容既有 | 内部转到新规则；旧请求不能绕过版本和记录要求 |
| POST /api/instances/:id/bind | 扩展既有 | 门槛变为实际制造 verified + 版本可用；避免并发绑定 |
| POST /api/device/poll | 尽量兼容 | 保留设备身份、commands、acks、events；扩展字段按协议版本约定 |
| POST /api/designs/:id/publish | 扩展既有 | 显式确定公开文字及文件快照，不随目录内容变化 |
| GET /api/state | 扩展既有 | 只提供摘要和必要 URL；大模型/照片不内嵌，避免每次全量传输 |

旧 /review 与 /package 接口需要兼容策略：设计审查不能绕过版本批准；旧 package 返回明确草案，或迁移到确定版本后再导出，不能猜测目录中“最新文件”作为最终制造文件。

错误统一提供稳定 code、可读 message 和可选 task_id/request_id；错误日志不回显 API key 或完整私有内容。

## 4. 事务与文件一致性

当前 Store.execute 每次独立提交。新增多步骤业务应使用已有 connect 的事务上下文，不把业务原子性寄托在若干独立 execute 上。

- 审批：核对版本状态、检查与 manifest，比较预期状态并更新，写入审核记录。
- 制作：核对 approved 版本、创建实例或新 attempt、写记录、更新阶段，单事务完成。
- 绑定：核对实例、版本、设备与活跃命令，在事务内创建唯一有效绑定意图；重试返回原命令。
- 事件：去重检查、业务应用与事件持久化同事务处理；相同 ID 不同 payload 拒绝为冲突，不能当作成功重试。
- 文件先写服务端暂存目录，校验后原子改名，再提交数据库引用；DB 失败产生的孤儿文件由受控清理任务处理。
- 版本批准后再次读取时核验文件存在与 manifest 哈希；缺失/损坏中止制造包导出并报错。
- 不在持有 SQLite 写事务期间调用 Tripo、处理大模型或等待打印。

## 5. 隐私、公开和删除

| 资源 | 默认可见性 | 公开/删除规则 |
|---|---|---|
| 原始记忆/参考照片 | 仅所有者 | 不因设计公开自动公开；删除前说明已确认发送的输入无法保证从供应商回收 |
| 生成输入快照 | 仅所有者 | 只在明确选定用于展示时复制为公开说明；不直接暴露整个内部 request |
| Tripo 原稿 | 仅所有者 | 作为显式公开资产才开放；原稿属性/文件名需检查私人内容 |
| 制造版本 | 仅所有者 | 发布选择具体文件和字段快照；后续修正不自动加入公开包 |
| 制作照片/尺寸/失败记录 | 仅所有者 | 单独选定公开材料；不把个人工作路径和照片自动打包 |
| 设备凭据 | 不公开 | 数据库存哈希；只在创建/轮换时返回明文；不进入普通状态与日志 |
| 已被二创的来源 | 可公开的来源标识 | 撤回阻止未来下载，不修改他人的已保存设计；保留必要来源记录 |

MVP 不引入复杂组织权限。默认作品所有者兼制作记录维护者；将“人工审核”标明为自检或指定制作人员记录，不称为第三方认证。如果多人共享制作权限，应单独新增明确授权机制，不能默认任何登录者都可审核。

原图尽量去除不需要的 EXIF/位置元数据；只有用户确认的内容发送第三方。图片删除采取引用检查：删除记忆不应破坏生成来源快照或制造历史；记录仍引用时明确保留范围，真正无引用时才进入清理。

## 6. 任务预算、重试与输入限制

- 配置按当前账户可用模型确定；模型、种子、输入快照和实际结果需保存。
- 每用户现有同时生成上限可以保留。额外增加每批运行的新付费提交次数限制或明确预算额度；无法精确预估费用时显示未知，不显示 0 元。
- 只对查询、下载等可安全恢复步骤有限重试。外部转换也可能消耗额度，必须纳入提交记录和重复防护。
- 图片大小、像素数、模型体积、转换时间和资源上限作为配置与测试输入，首轮真实样例后冻结。不以官网最大上限直接作为本机安全上限。
- 错误分类至少包含：未配置/未授权、输入不支持、预算拦截、提交未知、任务失败、下载失败、格式不支持、转换超时、需人工处理。

## 7. 旧数据迁移

1. 用一致性备份固定当前数据库与资产；记录版本与数量。
2. 在数据库副本执行迁移，保留旧字段兼容读；把现有目录建立为 legacy 候选 manifest。
3. 旧 reviewed 不自动映射到制造 approved；旧 simulated bound 保持模拟，不授予真实绑定资格。
4. 若存在真实旧实例，没有明确制造文件证据时标记 legacy_unverified，不伪造文件版本或销毁实例。
5. 对迁移数量、关联和资产哈希验证，重复执行不得重复创建版本。
6. 所有可逆迁移先验证；无法安全降级时使用停机备份恢复，并明确迁移后新数据如何保留，不能直接用旧库覆盖新记录。

迁移文件和运行日志作为 DA-02 交付物，不能仅在 README 写操作说明而不做样本演练。

## 8. 实施前冻结的六个决策

- 真实 Tripo 模型/返回格式和转换路径。
- 经试片验证的首版接口以及版本改变条件。
- 图片与模型上传限制和人工修正版导入方式。
- 审核所需证据、审核主体与撤销后的处理。
- NFC 安装/移除去抖、未知标签和离线使用行为。
- 公开分享文件集合及删除时保留哪些来源记录。

这些决策由真实样例和台架结果驱动。先完成相关实验，再把选项冻结为实现合同。
