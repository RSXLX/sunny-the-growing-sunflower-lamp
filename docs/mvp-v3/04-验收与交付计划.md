# BLOOM 验收与交付计划 v3

日期：2026-09-22。以下是待执行验收计划，PASS 必须有本次版本证据。所有阈值若非已有协议或产品目标，均需在执行前冻结并记录，不把建议阈值当成实测结果。

## 1. 证据等级与状态

软件实现、自动检查、实际浏览器、供应商真实调用、板级验证、实体制造、用户试用、对外发布分别记录。推荐状态：NOT_RUN / PASS / FAIL / BLOCKED / PARTIAL / WAIVED；WAIVED 必须说明范围变化且不得计入原要求通过。

证据位置建议：`evidence/YYYY-MM-DD/<任务ID>/`。保留源码 commit（未提交时保存工作区快照/哈希）、环境、应用配置指纹（不含秘密）、固件版本、接口版本、模型/制造哈希与执行人。原交付 evidence 不覆盖。

## 3. 实物测试的记录内容

测试前由硬件负责人确定：环境温度、供电、实际 LED/驱动/材料、运行档位、测试时长、测点、温度或其他限值、停止条件、保护触发方式和仪器。计划不编造材料安全温度或公差。

每次记录至少包括：

- 实物实例、制造版本、接口、固件和接线版本。
- 材料、打印方向、后处理、关键实测尺寸及装配方式。
- 主灯/投影分别的测点和结果；传感器缺失/异常时的实际关闭行为。
- 标签位置、读距、连续20次换装的逐次结果、失败时的日志。
- 结构固定、镜片/扩散片保持、线束拉扯及稳定性检查结果。
- 已知限制和适用运行条件。

主灯通过不自动证明分体投影通过。一次静态装配不等于长期耐久或量产认证。

## 4. 发布准入

### R0 参赛目标版

必须：真实 Tripo 原稿和来源证据、可安装 AI 外装、真实主灯/NFC 闭环、软件可操作、关键权限/任务/命令回归、运行包与真实演示素材、已知限制。可以使用受控本地命令与人工制作记录代替完整管理界面，但需明确呈现。

不允许以模拟设备回执、参数化样例、旧图片或模型渲染替代真实实体。若改成纯软件赛道，重写交付范围和验收，不能沿用实体完成声明。

### R1 完整 MVP

完成任务清单全部适用 R0+R1 项；图文输入、版本/审批/返工/证据、权限与分享、主灯/投影、浏览器与硬件异常、迁移/备份恢复和用户试用均有结果。参赛提交 DM-02 只在实际参赛时适用，不是产品本身上线条件。

若某项取消，需记录范围变更、用户影响和新名称/叙事，不能只将测试标记 WAIVED 而保持原承诺。

### 缺陷准入规则

- 阻断：实物风险、私有数据泄露、重复付费、数据丢失、制造版本错配、故障保护失效、主链不可用；未解决不得发布对应能力。
- 高优先：可恢复但频繁失败、关键设备状态错误、误导制造状态；需修复或明确缩减范围。
- 一般：非核心布局、文案和增强体验；可记录后排，但不影响完整流程可操作。

同一问题修复后执行定向复测；只在改动影响更广时扩大回归，不无意义反复跑全部测试。

## 5. 一条端到端验收脚本

1. 在干净测试目录启动，使用真实测试账户，创建设备并配置对应固件。
2. 保存私有记忆和参考图，确认将发送的图文内容。
3. 发起真实 Tripo 任务，刷新/重启一次，确认未发生第二次计费提交。
4. 查看真实原稿，生成适配候选；不支持格式时应明确失败或进入人工流程。
5. 导入人工修正版，建立制造版本并完成审核；尝试修改已审核文件应被阻止或创建新版本。
6. 下载固定版本制造包，核对哈希，记录切片/打印/后处理。
7. 创建真实实例，录入装配记录，完成 NFC 写入读回、移除再安装。
8. 检查实际灯光和网页状态；断网后本地操作，再重连验证过期命令不执行。
9. 发布选定设计快照，第二账号访问并二创；确认私人记忆/原图/证据未自动泄露。
10. 备份并恢复到独立目录，确认账号、资产、版本、实例和公开内容一致。

录像允许将历史打印过程单独插入，但必须对应同一制造版本并标明时间，不能表现为现场即时完成。

## 6. 用户试用观察

建议招募3–5人，记录每人的首个任务完成情况、需要解释的位置、选择哪张参考图、是否理解人工制作等待、是否愿意继续创作及原因。计时分开记录软件操作、生成等待、工程修正和打印，不能把多天制造时间隐藏在“几秒生成”指标里。

产品改进优先顺序：无法理解下一步 → 实际失败/误导状态 → 操作繁琐 → 视觉美化。试用不承诺销量和支付意愿已经验证。

## 7. 交付目录和清单

```text
release/<版本>/
  source-manifest.json       源码/依赖版本和构建信息
  app/                      可运行应用或明确的源码运行包
  config/                   仅示例配置
  hardware/                 固件、接线、BOM、CAD和实际制造版本
  evidence/                 脱敏后可交付的验证记录
  docs/                     启动、制作、使用、故障、备份恢复
  demo/                     流程录制、视觉素材、工具使用证据
  SHA256SUMS.txt             当前交付文件校验
```

交付前检查：无 API key、设备 token、私人日记或未获同意的照片；原始物理实例证据和公开展示素材分别处理。制造许可/公开权利由作品维护者确认，不因使用 AI 工具自动推定。

## 8. 运行与交接

- 运行目标默认本地/可信局域网，单服务进程；说明端口、主机地址和数据目录。
- 记录配置更改、工具链版本和模型配置，不在日常日志打印秘密。
- 备份涵盖 SQLite 与引用资产；明确一致性方案和停机要求；至少一次独立目录恢复成功。
- 冷启动检查：服务健康、目录权限、必需转换工具、设备离线提示，不能因有 token 就显示在线。
- 故障排查按任务/设备/实例 ID 关联，诊断包脱敏。
- 如需公网展示，先完成 EX-03 的独立方案与验收，不能直接绑定公网地址当作部署完成。
